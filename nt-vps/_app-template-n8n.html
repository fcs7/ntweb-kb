O que é o n8n

O n8n é uma plataforma de automação de fluxos de trabalho que permite conectar centenas de aplicações e serviços por meio de uma interface visual de arrastar e soltar. Em vez de escrever código, o usuário monta um fluxo arrastando blocos (chamados de "nós") que representam ações como "ler e-mail", "enviar mensagem no Slack", "consultar API", "atualizar planilha do Google" ou "salvar registro no banco de dados".

O projeto é mantido pela empresa n8n.io e oferecido em duas modalidades: uma versão hospedada na nuvem do fornecedor e a versão self-hosted, que é a que roda no template da NTWeb. A versão self-hosted dá ao cliente controle total sobre os dados e elimina o custo recorrente da assinatura na nuvem.

O que vem pronto na VPS NT

O template n8n da NTWeb (VMID 5101) entrega o n8n rodando em contêiner Docker, com basic authentication ativada por padrão. A senha de acesso é gerada automaticamente no primeiro boot e fica disponível em /root/credentials.txt.

Como acessar pela primeira vez

Após o provisionamento, o cliente acessa http://<IP>:5678 e é apresentado a um diálogo de autenticação básica. Usuário é admin; a senha está em /root/credentials.txt, acessível por SSH na porta 2222.

Logo após o login da basic auth, o n8n exibe a tela de configuração do usuário "owner" — esse é o administrador da instância. Após criar o owner, o painel completo do n8n fica disponível e o cliente pode começar a montar os primeiros fluxos.

Casos de uso típicos

Um caso clássico é a automação de leads: quando um formulário é preenchido no site, o n8n recebe os dados via webhook, valida o CNPJ em uma API pública, salva o lead no CRM, dispara um e-mail de boas-vindas e notifica a equipe comercial no Slack — tudo em segundos, sem ação humana.

Outras automações comuns incluem sincronizar produtos entre uma loja Shopify e o ERP da empresa, enviar relatórios diários de métricas para um canal interno, processar arquivos enviados por e-mail e arquivá-los em pastas organizadas no Drive, e integrar sistemas legados que não têm conector nativo entre si.

Cuidados e boas práticas

Por padrão, o n8n exige HTTPS para funcionar com cookies seguros. Quando o cliente acessa o painel apenas pelo IP da VPS, sem certificado TLS, o sistema mostra um aviso sobre cookie inseguro. Há duas formas de resolver: desabilitar o cookie seguro temporariamente (rápido, ideal para testes) ou colocar um proxy HTTPS na frente do n8n (recomendado para produção). O arquivo /root/LEIA-ME.txt traz o passo a passo das duas opções.

O volume Docker n8n_data guarda todos os fluxos e credenciais criptografadas do n8n. Backup desse volume é essencial antes de qualquer atualização. Em produção, o cliente também deve configurar a variável WEBHOOK_URL com o domínio público correto, sob pena de webhooks externos falharem.

Perguntas frequentes

O n8n é totalmente gratuito?

A versão self-hosted que roda no template da NTWeb é open-source sob a licença Sustainable Use, gratuita para uso interno. A empresa n8n.io oferece licenças comerciais separadas para quem quer revender o produto a terceiros.

Quantos fluxos posso rodar em uma VPS de 2 GB?

Para fluxos simples e de baixa frequência, dezenas. Para fluxos pesados (manipulação de arquivos grandes, IA generativa, lotes de milhares de registros), recomenda-se subir para 4 GB ou mais.

Posso integrar com sistemas que não têm conector pronto?

Sim. O n8n tem nós genéricos de HTTP Request e Function (JavaScript) que permitem chamar qualquer API ou escrever lógica personalizada. Praticamente qualquer sistema com API REST ou webhook é integrável.
